# /write-conclusion

Черновик, который пользователь потом правит. Главное — звучать как автор и опираться только на реальные числа.

## 1. Прочитать стиль

Перед написанием прочитать `style-guide.md` (рядом с этим файлом) целиком. Это описание голоса автора по выводам прошлого семестра: смесь аналитической плотности `lab_1` и живости `lab_3`.

## 2. Собрать факты

- Локальный вывод: outputs ячеек над местом вставки и данные, по которым построен график — `runs/<run>/summary.json`, `history.csv`, `predictions.csv` (Plotly-фигура в outputs чисел не содержит, поэтому числа берём из слепка рана).
- Финальный вывод: `task/task.md` (что требовалось), `reports/results.md` и `reports/iterations/*.md` — там история решений, неудачи и «почему отказались»; это лучший материал для честных авторских ремарок.
- Выписать для себя 2–4 конкретных факта с числами. Если для графика нет данных в `runs/` — спросить у пользователя, что на нём видно, или взять числа из W&B/iteration-файлов. Ничего не выдумывать — ни чисел, ни ремарок о ходе работы, которых не было.

## 3. Написать

- Локальный: `> **Вывод:**` + 1–3 абзаца (результат → контраст → причина → интерпретация/следующий шаг). Короткий — в одну строку после `> **Вывод:**`.
- Финальный: заголовки `## 1. Обзор результатов`, `## 2. Анализ ошибок`, `## 3. Возможные направления улучшения` (подогнать под пункты задания). Списки — только в рекомендациях.
- 0–1 личная ремарка на вывод. Термины, модели, метрики, классы — в backticks. Числа — как в источнике, с той же точностью.

## 4. Вставить

- Вставить в ноутбук markdown-ячейкой сразу после соответствующей ячейки (NotebookEdit, `cell_type: markdown`), если пользователь не просил показать в чате.
- Сказать пользователю, какие места стоит проверить: где была интерпретация «вероятно», где личная ремарка — пусть подтвердит, что она правда про его опыт.
