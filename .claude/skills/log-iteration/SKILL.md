# /log-iteration

## 1. Собрать факты

- Определить лабу (аргумент или по контексту) и номер итерации: следующий после последнего `reports/iterations/vN.md`.
- Метрики — из реальных источников, по приоритету:
  1. `runs/vN/summary.json` (метрики, конфиг, устройство, ссылка на W&B) и `runs/vN/history.csv` (динамика по эпохам: где минимум val loss, есть ли переобучение). Если папки нет, а учили на PC — напомнить `git pull`;
  2. W&B по `tracker_url` из summary — если нужно что-то, чего нет в слепке: `uv run python -c "import wandb; r = wandb.Api().run('<entity/project/id>'); print(r.summary._json_dict)"`;
  3. outputs ноутбука и то, что пользователь написал в чате.
- Diff конфига — сравнить `config` из `runs/vN/summary.json` и `runs/v(N-1)/summary.json`. Изменения кода — `git diff` по `src/` с прошлого коммита итерации.
- Чего не хватает (например, test-метрик или ссылки на run) — спросить одним вопросом или оставить `TODO`, но не выдумывать.

## 2. Записать reports/iterations/vN.md

```markdown
# vN: <коротко суть итерации>

Дата: YYYY-MM-DD · Машина: Mac M4 / RTX 4090 · Run: <ссылка W&B или MLflow run id> · Время обучения: <если известно>

## Что изменилось относительно v(N-1)

| Параметр | v(N-1) | vN |
| --- | ---: | ---: |
| ... | ... | ... |

Изменения в коде: <модель/аугментации/loss/данные — 1–3 пункта>

## Результаты

| Модель | split | loss | <основная метрика> | <доп. метрика> |
| --- | --- | ---: | ---: | ---: |

Кривые обучения: <что видно — переобучение с эпохи K, плато, нестабильность>

## Сравнение с лучшим

Лучший до этого: vK — <метрика>. Сейчас: <метрика> (Δ <+/−>).

## Интерпретация

<почему так получилось — гипотезы, привязанные к числам>

## Что дальше

- <следующий эксперимент и ожидаемый эффект>
```

## 3. Обновить reports/results.md

Сводная таблица (создать, если нет):

```markdown
| Итерация | Суть | Модель | val <метрика> | test <метрика> | Run |
| --- | --- | --- | ---: | ---: | --- |
```

Лучшую строку выделить **жирным**. Не переписывать старые строки, кроме исправления явных ошибок.

## 4. Финал

Показать пользователю 2–3 строки: результат итерации, Δ к лучшему, предложенный следующий шаг. Если ноутбук ещё не показывает этот ран (графики через `load_run('vN')`) — предложить добавить через `/code-lab`. Коммит — только если попросит (`docs(labN): итерация vN — ...`).
