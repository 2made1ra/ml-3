# Лабораторная 1: Нейронные сети для табличных данных

Условие: `task/assignment.md` (оригинал: `task/lab-1.pdf`) · Разобрано: 2026-10-31 · Дедлайн: 2026-11-01 23:59, далее штраф 1 %/день (не больше 50 %) · Доска: DL-1

## Цель

Сравнить классический бустинг и табличные нейросети на одном наборе данных: две архитектуры из учебных примеров (часть I) и две самостоятельно подключённые (часть II). Набор и test те же, что в ml-2 ЛР1, поэтому результаты сравнимы и с прошлым семестром.

## Решения

- Объём → максимум баллов: часть I + часть II с двумя новыми архитектурами (пользователь).
- Датасет → UCI Wine Quality, красное вино, 1599 объектов, 11 числовых признаков. Тот же набор был в ML сем. 1 и в ml-2 ЛР1 (пользователь: «тот, что в прошлом семестре»; проверено по `ml-2/LAB_I`). Ссылка `yasserh/wine-quality-dataset` ведёт на WineQT.csv: это 1143 строки того же вина + `Id`, в прошлых лабах его не было. Источник: Kaggle `uciml/red-wine-quality-cortez-et-al-2009`, версия закреплена в `src/data.py`.
- Задача → мультиклассовая классификация `quality` (классы 3–8, сильный дисбаланс), как в ml-2 ЛР1: так результаты сравнимы с прошлым семестром (цель пользователя).
- Метрики → как в ml-2 ЛР1: F1 macro (основная, по ней выбор на val), balanced accuracy, F1 weighted, ROC AUC OvR.
- Разбиение → test тот же, что в ml-2 ЛР1: stratified 20 %, `random_state=42` на всех 1599 строках, 320 объектов. Остальные 1279 → train / val stratified 80/20, seed 42: 1023 / 256.
- Признаки → 11 исходных + 5 производных из ml-2 ЛР1 (`total_acidity`, `vol_fixed_ratio`, `free_so2_ratio`, `alc_density_prod`, `sugar_alc_ratio`). Масштабирование обучается только на train.
- Baseline → CatBoost с параметрами Optuna из ml-2 ЛР1 (`auto_class_weights='Balanced'`), обучен на нашем train, early stopping по val. В итоговой таблице — справочные test-метрики RF и CatBoost из ml-2 ЛР1 (тот же test).
- Архитектуры части I → FT-Transformer + GANDALF (пользователь). Обе через `pytorch_tabular`: GANDALF есть только там, одна библиотека на обе модели, внутри Lightning.
- Архитектуры части II → TabLDM + TabM (пользователь). Это разные подходы: предобученная foundation-модель без обучения на наших данных против сети, обученной с нуля.
  - TabLDM (Xiaomi, 2026, arXiv 2609.03880): in-context learning, как TabPFN. Пакет ставится из git `xiaomi-research/xiaomi-tabldm` (на PyPI его нет), коммит закреплён в `uv.lock`. Веса — `occams/Xiaomi-TabLDM`, `checkpoints/clf_default.ckpt`, ревизия HF закреплена в коде. Устройство передаём из `get_device()`, то есть MPS. Авторы заявляют только CUDA и CPU, поэтому MPS проверяем на этапе 6; при сбое TabLDM идёт на CPU, причина — в 2.3. Официально поддерживает Python ≤ 3.12, работу на 3.13 проверяем на этапе 6. Если не заработает — остановиться и принять решение вместе с пользователем, без самостоятельной замены. Кандидат на замену — TabICL (`tabicl`, тот же подход). Причину замены объяснить в 2.3.
  - TabM (Yandex, ICLR 2025): пакеты `tabm` + `rtdl_num_embeddings`, обучение нашим циклом в `src/train.py`.
- Машина → вся лаба на Mac M4, PC не используется (пользователь). `/train` и `/tune` дают команды только для Mac.
- FAST_MODE и Run all → наш флоу (пользователь). Обучение в `src/train.py` → `runs/vN/`, ноутбук только читает `runs/`. Run all заново строит отчёт с теми же числами. Переобучение: `uv run python -m src.train` с тем же seed и `git_commit` из `summary.json`. FAST_MODE = `SMOKE=1`.
- Ручные объекты и permutation importance → считаются в конце обучения каждой финальной модели тем же pipeline и сохраняются в `runs/vN/`.

## Ограничения

- Preprocessing обучается только на train; val — выбор архитектуры, эпох и гиперпараметров; test — только итоговая оценка.
- Все модели — на одном разбиении и с одинаковыми метриками.
- Ручные объекты (≥ 10) — не test-выборка: по ним не считают метрики и не подбирают гиперпараметры. Проходят тот же pipeline, без ручного кодирования и нормализации.
- Категориальных признаков нет: пункт «объект с категорией, которой не было в train» неприменим. Вместо него — объекты со значениями за пределами train (например, `alcohol` выше максимума); в ноутбуке пояснить почему.
- Часть II: нельзя MLP / ResNet, FT-Transformer, TabNet, TabTransformer, GANDALF. Если библиотека не ставится — заменить и коротко объяснить почему, окружение не чинить.
- Нельзя данные соревнования Kaggle текущего семестра.
