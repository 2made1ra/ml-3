# Нейронные сети для табличных данных

## I. Нейронные сети для табличных данных по учебным примерам — до 10 баллов

### 1.1. Выберите набор данных

Выберите набор данных для задачи **классификации** или **регрессии**.

Классификация — целевая переменная принимает конечное число классов.
Регрессия — целевая переменная числовая и может принимать большое количество значений.

В идеале используйте один из наборов данных, который вы уже «крутили» ранее.

**Древнее зло пробудилось.**

Также разрешается использовать данные:

- из вашей проектной работы;
- из вашей рабочей деятельности, если этими данными можно делиться;
- из открытых источников: OpenML, Kaggle и т. п.

Нельзя использовать данные из соревнования Kaggle текущего семестра.

Ориентиры для набора данных:

- от **5 содержательных признаков** без учёта целевой переменной;
- от **1000 объектов**, желательно больше;
- желательно наличие как числовых, так и категориальных признаков.

Примеры допустимых наборов данных:

- Прогнозирование оттока клиентов: https://www.kaggle.com/competitions/customer-churn-prediction-2020
- Кредитный скоринг: https://www.openml.org/search?type=data&sort=runs&status=active&id=31
- Предсказание цены дома: https://www.kaggle.com/competitions/house-prices-advanced-regression-techniques

Можно выбрать и любой другой подходящий набор данных.

### 1.2. Предварительная обработка и baseline — до 2 баллов

Выполните адекватную предварительную обработку данных.

Если вы уже выполняли EDA и preprocessing этого набора данных в предыдущей лабораторной работе — отлично. Можно сделать ссылку на предыдущую работу и показать только итоговый pipeline и необходимые результаты.

Необходимо разделить данные как минимум на:

**train / validation / test**

При этом:

- preprocessing обучается **только на train**;
- `train` используется для обучения модели;
- `validation` используется для выбора архитектуры, эпох и гиперпараметров;
- `test` используется только для итоговой оценки.

Не используйте test для выбора параметров модели.

Добавьте хотя бы один классический tabular baseline, например:

- CatBoost;
- LightGBM;
- XGBoost;
- либо сильную модель, полученную вами в предыдущих лабораторных работах.

Все сравниваемые модели должны использовать **одно и то же разбиение данных** и одинаковые итоговые метрики.

Для нейросетей обратите внимание на масштаб числовых признаков и целевой переменной. Если это необходимо для выбранной модели, выполните стандартизацию target, обучив преобразование только на train.

### 1.3. Выберите две нейросетевые архитектуры из учебных примеров — до 2 баллов

В учебных блокнотах рассмотрены:

- **MLP / tabular ResNet** — считаются одним семейством;
- **FT-Transformer**;
- **TabNet**;
- **TabTransformer**;
- **GANDALF**.

Выберите **две архитектуры**.

Желательно выбирать модели, основанные на разных идеях. Например:

- ResNet + FT-Transformer;
- TabNet + TabTransformer;
- FT-Transformer + GANDALF;
- TabNet + GANDALF.

Сначала запустите модели в разумной базовой конфигурации — условно «из коробки».

Для каждой модели зафиксируйте:

- основные параметры архитектуры;
- количество эпох;
- validation-метрику;
- желательно время обучения;
- при желании — количество обучаемых параметров.

#### Важно про FAST_MODE

В учебных блокнотах присутствует режим:

```python
FAST_MODE = True
```

Он предназначен **только для проверки того, что notebook запускается и pipeline работает**.

В FAST-режиме используется меньше данных и/или эпох, поэтому качество моделей может быть очень плохим.

**Метрики из FAST_MODE нельзя использовать для итоговых выводов и сравнения архитектур.**

Для содержательных экспериментов переключите:

```python
FAST_MODE = False
```

### 1.4. Исследуйте и оптимизируйте выбранные модели — до 3 баллов

Попробуйте улучшить выбранные архитектуры.

Не требуется запускать огромный Grid Search или AutoML на сотни экспериментов.

Гораздо важнее показать, что вы понимаете:

> какой параметр меняете → зачем его меняете → какой результат получили.

Например, можно исследовать следующие параметры.

#### MLP / ResNet

- количество блоков;
- размер скрытых слоёв;
- dropout;
- learning rate;
- weight decay.

#### FT-Transformer

- количество Transformer-блоков;
- размер token embedding;
- количество attention heads;
- dropout;
- learning rate.

#### TabNet

- `n_d`;
- `n_a`;
- `n_steps`;
- `gamma`;
- `lambda_sparse`;
- размер embeddings;
- learning rate.

#### TabTransformer

- размер embeddings;
- количество attention heads;
- количество attention blocks;
- dropout;
- learning rate.

#### GANDALF

- количество GFLU stages;
- dropout;
- начальная sparsity;
- learnable sparsity;
- learning rate.

Покажите несколько разумных экспериментов и кратко прокомментируйте результаты.

Отдельный плюс в карму — исследование **unsupervised / self-supervised pretraining**, если выбранная архитектура это поддерживает.

### 1.5. Сравните модели и исследуйте их поведение — до 3 баллов

Сравните:

- классический tabular baseline;
- первую выбранную нейросеть;
- вторую выбранную нейросеть.

Недостаточно написать:

> Модель A дала R² = 0.82, модель B — 0.79, поэтому A лучше.

Ожидается хотя бы небольшой анализ:

- итоговых метрик;
- распределения ошибок;
- крупных ошибок;
- возможных причин различий между моделями;
- поведения моделей на разных объектах.

Для регрессии можно использовать, например:

- RMSE;
- MAE;
- R²;
- `actual vs predicted`;
- распределение абсолютных ошибок.

Для классификации выбирайте метрики в соответствии с особенностями задачи и распределением классов.

Также желательно исследовать **feature importance или её аналоги**.

Для честного сравнения разных архитектур рекомендуется использовать хотя бы один общий model-agnostic метод, например:

**Permutation Importance**

Если модель имеет собственные механизмы интерпретации — например masks у TabNet — покажите их дополнительно и сравните с общим методом.

## Обязательная проверка на новых данных, созданных вручную

Создайте вручную **не менее 10 новых объектов**, которых нет в исходном наборе данных.

Получите для них предсказания:

- классического baseline;
- первой нейросети;
- второй нейросети.

Новые объекты должны проходить **тот же preprocessing pipeline**, что и реальные данные.

Не кодируйте категории и не нормализуйте признаки вручную отдельно от основного pipeline.

Желательно создать несколько разных типов объектов:

- обычный объект, похожий на объекты обучающей выборки;
- несколько похожих объектов, в которых осмысленно изменяется один или несколько признаков;
- необычный, но возможный объект;
- при наличии категориальных признаков — объект с категорией, которой не было в train.

Например, для задачи оценки стоимости автомобиля можно создать несколько почти одинаковых автомобилей:

```
Toyota Prius, 2008 год, пробег 280 000 км
Toyota Prius, 2014 год, пробег 150 000 км
Toyota Prius, 2020 год, пробег  50 000 км
```

При этом остальные признаки оставить одинаковыми.

Получится небольшой **counterfactual sanity check**: можно посмотреть, насколько разумно модель реагирует на изменение года выпуска и пробега.

Важно:

**созданные вручную данные не являются дополнительной test-выборкой.**

У таких объектов обычно нет известного правильного target, поэтому по ним нельзя оценивать RMSE, R² и т. п.

Это проверка цепочки:

```
новый объект
      ↓
preprocessing
      ↓
model
      ↓
prediction
```

Прокомментируйте:

- выглядит ли prediction правдоподобно;
- меняется ли он ожидаемым образом;
- насколько расходятся разные модели;
- что произошло с неизвестной категорией;
- находится ли объект примерно в области обучающих данных;
- каким predictions стоит доверять меньше.

Результаты на придуманных объектах **нельзя использовать для подбора гиперпараметров**.

Правдоподобный prediction не доказывает качество модели.
Неправдоподобный prediction — хороший повод проверить модель и pipeline.

### Ограничение по баллам

Если выполнена только **одна нейросетевая архитектура**, максимальная оценка за часть I — **7 баллов**.

### 2.4. Обучите и исследуйте выбранные модели — до 6 баллов

# Требования к оформлению notebook

Notebook должен читаться как небольшой технический отчёт:

```
Постановка задачи
        ↓
Данные
        ↓
Preprocessing
        ↓
Baseline
        ↓
Neural models
        ↓
Hyperparameter experiments
        ↓
Test
        ↓
Анализ ошибок
        ↓
Интерпретация
        ↓
Новые ручные объекты
        ↓
Выводы
```

Хочется видеть:

- понятную структуру и заголовки разных уровней;
- комментарии не только к коду, но и к полученным результатам;
- отсутствие запущенных ячеек с ошибками;
- понятные имена переменных;
- адекватно оформленные графики;
- подписи и пояснения к визуализациям;
- разумное количество рисунков;
- итоговые таблицы сравнения;
- выводы по проведённым экспериментам.

Не нужно присылать 100 графиков без комментариев.

Оставьте визуализации, которые помогают рассказать историю эксперимента.

Интерактивные Plotly-графики использовать можно и приветствуется.
