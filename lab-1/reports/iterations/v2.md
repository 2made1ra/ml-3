# v2: FT-Transformer «из коробки» (pytorch_tabular)

Дата: 2026-10-31 · Машина: Mac M4 (MPS) · Коммит: f9ab14c, `git_dirty: true` (код этапа 2 ещё не закоммичен) · MLflow run: b3c27df5d8214de0af46c9eb1dd35c85 · Время обучения: 10.2 с

Гипотеза: FT-Transformer с параметрами `pytorch_tabular` по умолчанию → заметно выше Dummy (0.0995), но не выше CatBoost v1 (0.2925): на 1023 объектах без весов классов редкие классы почти не предсказываются.

## Что изменилось относительно v1

Новая модель, сравнение с CatBoost v1 по тому же разбиению и метрикам.

| Параметр | v1 (CatBoost) | v2 | Роль |
| --- | ---: | ---: | --- |
| модель | CatBoost | FT-Transformer | изучаемый |
| input_embed_dim / heads / attn blocks | — | 32 / 8 / 6 | вспомогательный (default) |
| attn_dropout / ff_dropout | — | 0.1 / 0.1 | вспомогательный (default) |
| optimizer, lr, weight_decay | — | Adam, 1e-3, 1e-4 | вспомогательный |
| batch_size | — | 64 | вспомогательный |
| max epochs / patience по val loss | — | 200 / 20 | вспомогательный |
| веса классов | Balanced | нет (CrossEntropy) | вспомогательный |
| масштабирование | нет | standard, по train (внутри `pytorch_tabular`) | — |

Изменения в коде:
- `src/train.py`: путь `pytorch_tabular` (`make_tabular_model`, `fit`, `train_nn`, `benchmark_nn`), CLI `--model`, `--epochs`.
- `src/config.py`: `model`, `patience`, архитектурные поля `ft_*`, `gandalf_*` со значениями по умолчанию библиотеки; `epochs` 200, `num_workers` 0.
- Зависимости: `pytorch_tabular` 1.2.0, `pytorch-lightning` 2.6.6. `pandas` откатился 3.1 → 2.3.3 (требование `pytorch_tabular`). Старый `pytorch-lightning` 2.1.4 падал на импорте без `pkg_resources`.
- Найден и исправлен до обучения баг: `TabularModel.fit` по умолчанию берёт `seed=42` и игнорирует `TrainerConfig.seed`. Теперь `cfg.seed` передаётся в `fit` явно. Затронутых ранов нет.

Усложнения: `HistoryCallback` — `pytorch_tabular` не отдаёт историю по эпохам, а кривые обучения нужны для 1.3.

Sanity-проверки (скрипт в scratchpad):
- loss@init на train при разных seed: 2.67 / 1.35 / 2.70 (seed 0 / 1 / 42), ожидалось ln 6 ≈ 1.79. Метки и loss при этом корректны: у GANDALF на тех же данных 1.72–1.97. Причина — инициализация головы в библиотеке: std логитов при init 0.89 против 0.37 у GANDALF, предсказания на старте неравномерны по классам. «Из коробки» инициализацию не меняем.
- Overfit одной batch (16 объектов, все 6 классов, 300 шагов): loss 0.0019.

Параметров: 272 614. Эпох: 32, лучшая — 12.

Кривые обучения: val loss минимален на эпохе 12 (0.9685), к эпохе 32 растёт до 1.0992; train loss падает с 1.2986 до 0.7666. Переобучение с ~12-й эпохи, early stopping взял лучшую.

Test по классам: F1 у 5 / 6 / 7 — 0.664 / 0.589 / 0.346, у 3, 4, 8 — 0. Предсказания на test: 4 — 1, 5 — 150, 6 — 157, 7 — 12; классы 3 и 8 не предсказаны ни разу.

## Сравнение с лучшим

Лучший до этого: v1 (CatBoost) — val F1 macro 0.2925. Сейчас: 0.2742 (Δ −0.018).

Гипотеза: подтвердилась. Сильно выше Dummy (+0.175), чуть ниже CatBoost.

## Интерпретация

- Модель почти бинарная: 307 из 320 предсказаний на test — классы 5 и 6. F1 weighted (0.5755 на val) выше, чем у CatBoost (0.5274), а balanced accuracy ниже (0.2715 против 0.3343). Причина — нет весов классов: CatBoost с `Balanced` чаще рискует на редких классах.
- Val loss не сравним с CatBoost: у v1 loss взвешенный.
- Модель с 272 тыс. параметров на 1023 объектах переобучается уже после 12 эпох.
- Разница с CatBoost 0.018 на 256 объектах val — в пределах шума одного seed (см. v1, «Интерпретация»).
