# Как работать над лабой

Кто что делает:

- **Вы:** даёте условие, отвечаете на вопросы, решаете, кто запускает обучение, правите выводы, сдаёте и защищаете.
- **Opus** (основная сессия Claude Code): разбирает условие, планирует, пишет спецификации, проверяет код, анализирует результаты.
- **lab-coder** (Sonnet): пишет код по спецификации Opus.
- **Mac M4:** код, проверки, ноутбук, лёгкое обучение. **PC с RTX 4090:** тяжёлое обучение. Машину для всей лабы можно выбрать заранее — лаба 1 целиком на Mac.

Где что живёт:

| Что | Где | Роль |
| --- | --- | --- |
| Условие | `lab-N/task/assignment.md` + оригиналы в `task/` | текст задания |
| План, этапы, статусы | `lab-N/task/task.md` | источник истины по задачам |
| Числа | `lab-N/runs/vN/summary.json` | источник истины по результатам |
| Доска kvatask | эпик лабы, задача на этап | витрина `task.md` для вас |
| MLflow | `~/.mlflow/mlflow.db` на каждой машине | витрина ранов |

Пример по всему гайду — лаба 1 «Нейронные сети для табличных данных»: [lab-1/task/task.md](../lab-1/task/task.md).

**Автопилот: `/lab-flow N`.** Claude сам ведёт лабу по флоу ниже: определяет, на каком шаге лаба, и вызывает нужный скилл. Один этап — одна сессия: закрыв этап, Claude пишет «/clear, затем `/continue-lab`» и останавливается; в экспериментальных этапах — ещё и каждые 2 итерации. Всё нужное следующей сессии лежит в файлах (`task.md`, `reports/iterations/`, `runs/`, ноутбук), так контекст не тянет прошлые этапы и токены не тратятся на их перечитывание. Внутри этапа шаги идут без подтверждений; Claude спрашивает только в критических местах: неуверенность или неопределённость, которую он не может разрешить сам. Остаются интервью `/plan-lab` и настоящие развилки в коде. Обучение и `/tune` на Mac до 20 минут Claude запускает сам; более долгие и запуски на PC — по вашему решению. Коммиты Claude делает сам после каждого эксперимента: код перед раном (`feat`), результат после разбора (`run(lab1): vN — гипотеза, модель, метрика`); push — при закрытии этапа. Так каждый ран обучен на чистом коммите, а история git — журнал экспериментов. Если вернулись после перерыва больше часа — лучше `/clear` и `/continue-lab`, чем продолжать старую сессию. `/continue-lab` без аргументов берёт лабу по ветке `lab-N` и продолжает с того же места: состояние берётся из `task.md`, `runs/` и ноутбука. Гипотезы для экспериментов выбираете вы: в начале экспериментального этапа и после каждой проверенной пачки Claude по результатам предлагает варианты с чекбоксами (данные, гиперпараметры), выбранные записываются в «Гипотезы» этапа в `task.md`. Результаты Optuna разбираете вместе.

## 0. Подготовка

**Один раз на машине** — [README](../README.md), раздел «Один раз на машине»:
- prek-хуки;
- токены Kaggle и HF;
- `secrets.yaml` с ключом kvatask: на каждой машине свой ключ, файл не коммитится.

Инструменты доски появляются только в сессии, открытой после создания `secrets.yaml`.

**Как передать условие:**
- Лучше всего PDF (в браузере: «Печать → Сохранить как PDF») или текст в `.md`. Лаба 1: страница курса → PDF на 11 страниц.
- Скриншот длинной страницы при передаче сжимается. Первый вариант условия лабы 1 был скриншотом 197×2000 px, на нём читались только заголовки. В таком случае Claude не додумывает текст, а просит PDF.
- Файл кладите в `lab-N/task/`. Из `~/Downloads` Claude читать не может: это закрыто защитой macOS.

## 1. Старт: `/new-lab N`

```
/new-lab 1 lab-1/task/lab-1.pdf
```

0. Ветка `lab-N` от свежего `main`. Вся работа над лабой идёт в ней, в конце она сливается в `main` (раздел 5).
1. Разбор условия (`/plan-lab`): полный текст → `task/assignment.md`.
2. Интервью: до 4 вопросов о том, что условие оставляет на ваш выбор, у каждого — рекомендация.
3. План этапов → `task/task.md`.
4. Доска (`/kva-sync`): эпик лабы и задача на каждый этап, номера задач записываются в `task.md`.
5. Каркас лабы, uv-окружение, заготовка ноутбука по разделам условия.
6. Коммит каркаса и push ветки — по вашему подтверждению. Без push не работают ссылки с доски и обучение на PC.

Условие изменилось или вышла новая часть: `/plan-lab N` обновит план, сохранит отмеченные этапы и обновит доску.

### Пример: лаба 1

Интервью:

| Вопрос | Ответ |
| --- | --- |
| Какие части делаем (дедлайн завтра, штраф 1 %/день)? | Максимум: части I и II, по две архитектуры |
| Какой датасет (п. 1.1)? | Wine Quality, как в прошлом семестре, чтобы сравнить результаты |
| Какие две архитектуры из учебных (п. 1.3)? | FT-Transformer + GANDALF |
| Как совместить `FAST_MODE` и «Run all» с нашим флоу? | Наш флоу: ноутбук читает `runs/` |

Что Opus проверил и решил сам. Всё записано в «Решения» `task.md`, ничего не принято молча:

- Ссылка на датасет вела на WineQT (1143 строки), а в ml-2 ЛР1 был UCI red (1599 строк). Взят тот же UCI и тот же test (320 объектов), поэтому прошлые test-метрики сравнимы напрямую.
- Задача и метрики — как в ml-2 ЛР1: классификация `quality`, F1 macro, balanced accuracy.
- Baseline — CatBoost с параметрами Optuna из ml-2 ЛР1. Это «сильная модель из прошлых лабораторных», которую разрешает условие.
- FT-Transformer и GANDALF подключаются через одну библиотеку `pytorch_tabular`: GANDALF есть только в ней.
- Категориальных признаков нет, поэтому пункт «объект с неизвестной категорией» неприменим. Вместо него — объекты вне диапазона train.

Решения после интервью:

- Вся лаба на Mac.
- Часть II — TabLDM + TabM. TabLDM — свежая foundation-модель Xiaomi, которая не обучается на наших данных. TabM — ансамбль MLP, обучается с нуля.
- Если TabLDM не заработает на Python 3.13, замену решаем вместе; кандидат — TabICL.

Этапы (`task.md`) и задачи на доске:

| Этап | Пункты | Баллы | Доска |
| --- | --- | ---: | --- |
| 1. Данные, preprocessing, CatBoost baseline | 1.1–1.2 | 2 | DL-2 |
| 2. FT-Transformer и GANDALF «из коробки» | 1.3 | 2 | DL-3 |
| 3. Исследование гиперпараметров | 1.4 | 3 | DL-4 |
| 4. Сравнение, ошибки, importance | 1.5 | 3 (с этапом 5) | DL-5 |
| 5. Ручные объекты, часть I | обязательная проверка | — | DL-6 |
| 6. Протокол и подключение TabLDM и TabM | 2.1–2.3 | 2 + 4 | DL-7 |
| 7. Исследование TabLDM и TabM | 2.4 | 6 | DL-8 |
| 8. Итоговое сравнение и повтор ручных объектов | 2.5 | 3 | DL-9 |
| 9. Итоговые выводы и сдача | оформление | — | DL-10 |

Эпик лабы на доске — DL-1.

Так выглядит этап в `task.md`:

```markdown
### [ ] Этап 2. FT-Transformer и GANDALF «из коробки» — п. 1.3, 2 балла
- Требование: две архитектуры в разумной базовой конфигурации (`assignment.md`, 1.3).
- В ноутбуке: 1.3 — идея каждой архитектуры (2–3 предложения); таблица: основные параметры, число эпох, val F1 macro, время обучения, число параметров; кривые обучения.
- Как: `/code-lab stage 2` → `/train` → `/log-iteration` → `/write-conclusion`.
- Готово, когда: по рану на модель в `runs/`; smoke пройден; loss на старте ≈ ln 6 ≈ 1.79; одна batch переобучается.
- Результаты: —
- Доска: DL-3
```

Требования преподавателя для всей работы живут в разделе «Оформление и сдача» `task.md`, у каждого есть строка «В нашем флоу». В лабе 1:

- `FAST_MODE` = наш `SMOKE=1`. Smoke-раны не коммитятся.
- «Run all без ошибок»: ноутбук читает `runs/` и за секунды строит отчёт с теми же числами.
- Файл сдачи ≤ 10 МБ: размер проверяется после `/pack-submission`.

## 2. Доска kvatask

Доска показывает работу над лабой, но решает всё `task.md`.

- **Что на доске.** Эпик на лабу и задача на каждый этап. В описании задачи — все пункты этапа и блок «Подробно» со ссылками на `task.md`, `assignment.md` и отчёты итераций на GitHub.
- **Статусы:**
  - `todo` — новый этап;
  - `in_progress` — этап начат (`/lab-flow`, `/code-lab`);
  - `done` — этап отмечен `[x]` в `task.md`; в задачу добавляется комментарий-отчёт: что сделано, числа из `runs/`, гипотезы, отклонения от плана, усложнения, ссылки на отчёты итераций.
- **Изменить задачу:** правьте `task.md` сами или попросите Claude, затем `/kva-sync`. Правки, сделанные только на доске, не считаются.
- **Добавили задачу на доску вручную:** `/kva-sync` её покажет и предложит два варианта: новый этап через `/plan-lab` или разовая задача через `/code-lab`.
- **Закрыли задачу на доске, а в `task.md` этап не отмечен:** `/kva-sync` спросит. Если этап готов, сначала отмечается `task.md`, потом доска. Если нет, статус на доске возвращается.
- **Ссылки «Подробно»** открывают версию из ветки `lab-N` на GitHub, поэтому актуальны после push ветки. После слияния ветка остаётся, и ссылки продолжают работать.
- **Доска недоступна** (нет `secrets.yaml`, ключ отозван) — работа над лабой идёт без неё.

## 3. Этап за этапом

1. **Код:** `/code-lab all` берёт первый неотмеченный этап и после каждого ждёт вашего «дальше». Конкретный этап — `/code-lab stage K`.
   Внутри: Opus пишет спецификацию → lab-coder пишет код → Opus проверяет: ruff, ty, smoke, sanity-проверки, устройство, ревью диффа. Итог — отчёт с разделом «Усложнения».
2. **Подбор гиперпараметров:** `/tune`, когда нужно подобрать lr или честно сравнить модели. В лабе 1 это этапы 3 и 7: сравнение архитектур честное, только если lr подобран для каждой.
3. **Обучение:** `/train`.
   - **Машина:** берётся из «Решений» `task.md`. Если её там нет, `/train` замерит время на Mac (`--benchmark`) и посоветует, где учить.
   - **Перед запуском** код закоммичен: тогда `git_commit` в `summary.json` точно указывает, на каком коде обучен ран.
   - **Кто запускает.** `/train` показывает команду и время и спрашивает: «Запусти ты» или «Запущу сам».
     - «Запусти ты»: Claude запускает на Mac в фоне, по окончании сообщает время и метрику и сам переходит к `/log-iteration`.
     - «Запущу сам»: вы запускаете команду и пишете «готово».
     - На PC запускаете всегда вы: доступа к нему у Claude нет.
     - `/tune` спрашивает так же.
4. **Устройство:**
   - **Выбор:** на PC — `cuda`, на Mac — `mps`.
   - **CPU:** только для модели, которая не работает на MPS или CUDA; причина записывается в код и отчёт. Бустинги (CatBoost) на Mac всегда на CPU: MPS они не поддерживают.
   - **Где проверить:** поле `device` в `runs/vN/summary.json`.
5. **Разбор итерации:** `/log-iteration` → `reports/iterations/vN.md` и `reports/results.md`.
6. **Выводы к разделу:** `/write-conclusion` пишет черновик `> **Вывод:**`, субагент `numbers-checker` (Haiku) сверяет каждое число с `runs/`, вы правите. Тот же субагент проверяет числа в `/lab-review`.
7. **Закрытие этапа:** когда выполнено «Готово, когда», этап отмечается `[x]` в `task.md`, и `/kva-sync` закрывает задачу на доске. Claude коммитит оставшиеся правки этапа (`docs`) и пушит ветку.

Лаба 1, этап 1 целиком:

```
/code-lab stage 1      # DL-2 → in_progress; src/data.py (загрузка, признаки, сплит), CatBoost в src/train.py, ячейки 1.1–1.2
/train                 # команда uv run python -m src.train --run v1 и вопрос «Запусти ты / Запущу сам»
/log-iteration         # reports/iterations/v1.md
/write-conclusion      # выводы к 1.1–1.2; этап → [x], DL-2 → done
```

## 4. Если что-то пошло не так

- **Баг:** `/code-lab исправь: <симптом>`, например `/code-lab исправь: val F1 macro выше train с первой эпохи`. Opus воспроизводит баг, находит причину, исправляет через lab-coder и проверяет, что воспроизведение больше не срабатывает. Если баг испортил прошлые раны, называет, какие переобучить.
- **Код не нравится:** `/code-lab перепиши <что> — <что не так и как хочу>`, например `/code-lab перепиши make_splits — хочу явные шаги вместо цикла`. Меняется только названное. Если переписывание лишь усложнит код, Opus скажет об этом до работы.
- **Правите сами:** после правок — `/code-lab review` → список проблем; исправления — по вашей просьбе. Чтобы агенты не трогали ваш код, пометьте его `# user-owned`: строкой над `def`/`class`, первой строкой файла или ячейки.
- **Выбранная модель или библиотека не работает** (не ставится, не поддерживает версию Python): Claude останавливается и предлагает варианты, замену решаем вместе. Пример — TabLDM в лабе 1: кандидат на замену записан в `task.md`, но сам Claude её не делает.

## 5. Выводы, сдача, защита

```
/write-conclusion      # «Итоговые выводы» — просмотр результатов и черновиков обязателен
/lab-review            # сверка с этапами task.md и «Оформлением и сдачей»; лучше в новой сессии (/clear)
/pack-submission       # единый ipynb → lab-N/submission/
/prep-defense          # вопросы к защите с ответами → reports/defense.md; /prep-defense quiz — тренировка
```

Лаба сдана — ветка сливается в `main`, только по вашему подтверждению. Ветку не удаляем: на неё ведут ссылки с доски.

```bash
git switch main && git pull && git merge --no-ff lab-N && git push
```

## Команды Mac и PC

Обучение на Mac (или «Запусти ты» в `/train`):

```bash
cd lab-N && uv run python -m src.train --run v1
```

Обучение на PC: закоммитить и запушить код на Mac, затем на PC (в ветке лабы):

```bash
git fetch && git switch lab-N && git pull && cd lab-N && uv sync
uv run python -m src.train --run v1
git add runs/v1 && git commit -m "run(labN): v1 — <суть>" && git push
```

Подбор гиперпараметров (на выбранной машине):

```bash
uv run python -m src.tune --study <имя> --trials N
git add runs/tune/<имя>.db && git commit -m "run(labN): tune <имя> — <цель>" && git push   # если на PC
```

После обучения на PC — на Mac:

```bash
git pull && cd lab-N && uv run python -m src.sync_mlflow   # ран с PC появится в MLflow на Mac
```
