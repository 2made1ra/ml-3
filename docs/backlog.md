# Бэклог

Идеи и улучшения инфраструктуры, которые отложены на потом.

## Секреты через SOPS + age

**Статус:** отложено (2026-10-31). Сейчас секреты — в штатных хранилищах инструментов на каждой машине (см. «Секреты» в `CLAUDE.md`).

**Когда вернуться:** когда секретов станет больше и их станет неудобно заводить руками на двух машинах (например, креды MLflow-хаба на VPS).

**Идея:** зашифрованный `secrets.enc.yaml` в git (SOPS + age), ключ age один раз переносится на PC; запуск через `sops exec-env secrets.enc.yaml 'uv run ...'`. Сервер не нужен.

## MLflow-хаб на VPS

**Статус:** идея, не начато (2026-10-31).

**Сейчас:** MLflow локально на каждой машине (`~/.mlflow/mlflow.db`). Раны с PC попадают на Mac через `runs/` в git и `uv run python -m src.sync_mlflow`. Живые кривые обучения на PC видны только в `mlflow ui` на самом PC.

**Хочу:** арендовать VPS и поднять там общий MLflow tracking-сервер, куда пишут обе машины.

**Зачем:**
- все раны с Mac и PC в одном UI без ручного импорта;
- живой мониторинг обучения на 4090 с Mac (и с телефона);
- можно хранить на сервере артефакты (чекпоинты лучших моделей), чтобы не таскать их между машинами вручную.

**Что сделать:**
- [ ] Выбрать VPS: мало CPU/RAM достаточно, диск — с запасом под артефакты (или отдельный S3-совместимый бакет).
- [ ] Поднять `mlflow server` (backend — PostgreSQL или SQLite, artifacts — диск/S3) за reverse proxy с HTTPS и авторизацией (basic auth в nginx/Caddy или встроенная auth MLflow) — сервер без авторизации в интернет не выставлять.
- [ ] Бэкапы базы MLflow.
- [ ] На обеих машинах задать `MLFLOW_TRACKING_URI` (и креды через `MLFLOW_TRACKING_USERNAME` / `MLFLOW_TRACKING_PASSWORD`) — `src/tracking.py` уже переключается на сервер, если переменная задана.
- [ ] Фолбэк в `src/tracking.py`: если сервер недоступен — предупреждение и `TRACKER=none`, обучение не должно падать (слепок `runs/` пишется всё равно).
- [ ] Перенести старые раны: `src/sync_mlflow.py` с заданным `MLFLOW_TRACKING_URI` импортирует `runs/` в хаб (проверить, что он пропускает раны, уже записанные в хаб напрямую).
- [ ] Обновить `CLAUDE.md`, `README.md`, скиллы `/train` и `/log-iteration`: `sync_mlflow` станет нужен только для старых ранов.

**Что не меняется:** `runs/` в git остаётся источником правды для ноутбука и выводов — хаб только витрина.
